# MangaKindle

Берёт ссылку на мангу с mangalib.me, скачивает главы, режет развороты,
приводит страницы под экран Kindle 11th gen (1072×1448, 300 ppi, серый)
и собирает готовый файл.

Личный инструмент для чтения на своём устройстве. Ничего не публикует,
никуда не раздаёт, защиту сайта не обходит.

## Что уже работает

Окно и командная строка: ссылка → PDF, AZW3 или EPUB, и сразу на Kindle
по USB. Отправка по почте — следующий этап.

## Окно

```bash
mangakindle-gui
```

Или пункт «MangaKindle» в меню приложений. Одно окно: поле ссылки,
обложка и название, список глав с чекбоксами («Все», «Снять», диапазон
вроде `1-3`), выбор формата, направления чтения и разворотов, выбор
«сразу на Kindle» или «в папку».

Вся работа идёт в фоновом потоке, окно не подвисает; «Отмена» работает
в любой момент. Кнопка «Токен 18+» — для закрытого раздела.

## Установка

Нужен [uv](https://docs.astral.sh/uv/). Python 3.13 он поставит сам.

```bash
git clone <репозиторий> mangakindle
cd mangakindle
uv sync
```

## Запуск

Посмотреть список глав:

```bash
uv run mangakindle "https://mangalib.me/ru/manga/1357--vagabond" --list
```

Выбранное всегда собирается **в один файл**: главы 1–3 — один PDF,
`all` — весь тайтл одним PDF. Нужны отдельные файлы по главам — `--split`.

```bash
mangakindle "https://mangalib.me/ru/manga/1357--vagabond" --chapters 1-3
```

Сразу на устройство, без промежуточной возни с файлами:

```bash
mangakindle "https://mangalib.me/ru/manga/1357--vagabond" --chapters 1-3 --to kindle
```

Весь тайтл одним файлом в EPUB, по файлу на главу:

```bash
mangakindle "https://mangalib.me/ru/manga/1357--vagabond" --chapters all --split --format epub
```

Если глава на сайте закрыта — сохрани страницы сам и собери из папки или архива:

```bash
uv run mangakindle --local ~/Загрузки/глава_5 --chapters 1
```

### Установка в систему (Linux)

Команда `mangakindle` в PATH, пункт в меню приложений и иконка:

```bash
uv tool install .          # команды mangakindle и mangakindle-gui
uv run python assets/make_icon.py
install -Dm644 assets/icons/mangakindle-48.png  ~/.local/share/icons/hicolor/48x48/apps/mangakindle.png
install -Dm644 assets/icons/mangakindle-128.png ~/.local/share/icons/hicolor/128x128/apps/mangakindle.png
install -Dm644 assets/icons/mangakindle-256.png ~/.local/share/icons/hicolor/256x256/apps/mangakindle.png
install -Dm644 assets/icons/mangakindle.svg     ~/.local/share/icons/hicolor/scalable/apps/mangakindle.svg
install -Dm644 assets/mangakindle.desktop       ~/.local/share/applications/mangakindle.desktop
# абсолютный путь в Exec: графическая сессия часто не видит ~/.local/bin
sed -i "s|^Exec=.*|Exec=$(command -v mangakindle-gui)|" ~/.local/share/applications/mangakindle.desktop
update-desktop-database ~/.local/share/applications
gtk-update-icon-cache -f -t ~/.local/share/icons/hicolor
```

Запуск из меню открывает терминал и спрашивает ссылку и главы —
пока GUI нет, это честный интерфейс, а не кнопка-пустышка.

### Ключи

| Ключ | Что делает |
|---|---|
| `--chapters` | `all`, `3`, `1-10`, `1,4,7-9` |
| `--split` | по файлу на главу вместо одного файла на весь выбор |
| `--to` | `folder` — в папку (по умолчанию), `kindle` — сразу на устройство по USB |
| `--eject` | отмонтировать Kindle после копирования |
| `--format` | `pdf` (для USB), `azw3` (USB + обложка на полке), `epub` (для почты), `cbz` |
| `--direction` | `rtl` — манга (по умолчанию), `ltr` — манхва и маньхуа |
| `--spread` | `split` — резать развороты пополам, `rotate`, `keep` |
| `--no-trim` | не обрезать поля страниц |
| `--no-cover` | не класть обложку с сайта первой страницей |
| `--quality` | качество JPEG, по умолчанию 85 |
| `--delay` | пауза между запросами, по умолчанию 0.7 сек |
| `--keep-cache` | не удалять скачанные страницы после сборки |
| `--out` | папка для готовых файлов |

## Отправка письмом (Send to Kindle)

Amazon принимает письмо с вложением на адрес `...@kindle.com` и сам
конвертирует EPUB в свой формат — поэтому по почте по умолчанию едет
EPUB, а не PDF.

```bash
mangakindle --setup-email     # адрес Kindle, SMTP, пароль приложения
mangakindle "ссылка" --chapters 1-10 --to email
```

В окне это пункт «Письмом на Kindle» и кнопка «Почта…».

Пароль лежит в keyring, в конфиге его нет. Для Gmail нужен **пароль
приложения**, обычный не подойдёт. Адрес отправителя должен быть в списке
разрешённых в аккаунте Amazon: Личные документы → Список адресов e-mail
для отправки. Это делается на сайте Amazon, приложение туда не лезет.

Письмо не резиновое: лимит по умолчанию 24 МБ (у Gmail потолок 25).
Если выбранное не влезает, файл режется на части прямо при сборке —
«Бродяга — гл1-20 часть 1.epub», «часть 2» и так далее, каждая уходит
отдельным письмом. Лимит меняется в конфиге: `max_email_mb`.

## Обложка

Первой страницей идёт обложка тайтла с сайта, в оглавлении на неё стоит
закладка. **На главном экране Kindle обложку показывает только AZW3**:
для PDF, залитого по USB, прошивка миниатюру не делает вообще — проверено
на 5.19.2, устройство индексирует файл, но полку оставляет пустой.

```bash
mangakindle "ссылка" --chapters 1-3 --format azw3 --to kindle
```

AZW3 собирается из нашего же EPUB через `ebook-convert` из calibre.
Нет calibre — приложение скажет об этом до скачивания, а не после.
При заливке по USB миниатюра кладётся в `system/thumbnails/` сразу,
так что обложка видна, не дожидаясь первого открытия книги.

Оговорка: calibre теряет разметку fixed-layout и направление чтения,
так что страницы в AZW3 могут лечь хуже, чем в PDF. Порядок страниц
при этом правильный — он задан при сборке. PDF остаётся форматом
с самой предсказуемой картинкой. Сайт отдаёт обложку небольшой (около 375×534), под экран её
тянет почти втрое — поэтому резкость для неё приглушена, иначе лезут
артефакты JPEG. Не нужна — `--no-cover`.

## Отправка на Kindle

`--to kindle` ищет подключённый том: на Linux — по наличию `documents/`
и `system/` в корне, на Windows — по метке тома `Kindle`. Если устройство
подключено, но не смонтировано, приложение просит `udisksctl` смонтировать.

Файл кладётся в `documents/`, запись сбрасывается на диск, размер
проверяется после копирования. `--eject` отмонтирует том, чтобы кабель
можно было выдернуть сразу.

Kindle в спящем режиме отключает режим накопителя — если устройство не
нашлось, разбуди экран. Готовые файлы в любом случае остаются в папке.

## Почему PDF для USB, а не EPUB

EPUB, скопированный в `documents/` по USB, Kindle не открывает: поддержка
EPUB есть только в Send to Kindle, где файл конвертируется на стороне Amazon.
Поэтому по USB — PDF со страницами ровно 1072×1448, он рендерится нативно
и на весь экран. Для почты — EPUB fixed-layout с чтением справа налево.

## Раздел 18+

Обычные тайтлы, включая 18+ на самом mangalib, качаются без всякого входа.
А вот закрытый раздел (hentailib и родня) отдаёт страницы только своему
аккаунту: список глав виден всем, а на запрос страниц сайт молча отвечает
«нет такой страницы».

Приложение туда ходит **под твоим аккаунтом, твоим же токеном**.
Достать его можно мышкой, ничего никуда не вставляя:

1. Войти на сайте в браузере.
2. F12 → вкладка Application → Local storage → адрес сайта.
3. Строка с ключом `auth` → правой кнопкой по значению → Copy value.
4. Выполнить `mangakindle --token` — он возьмёт скопированное из
   буфера, сам достанет оттуда `access_token`, проверит на сайте
   и только потом сохранит.

Консоль тоже годится, но **вставлять в неё чужой код не надо** —
браузер не зря на это ругается. Короткую строку `localStorage.auth`
можно набрать руками: она просто печатает то же самое значение.

```bash
mangakindle --token-help      # показать строку для консоли браузера
mangakindle --token           # взять из буфера, проверить, сохранить
mangakindle --token ТОКЕН     # то же самое, но вставить явно
mangakindle --forget-token    # удалить
```

В окне то же самое делает кнопка «Токен 18+»: там и строка для консоли,
и «Вставить из буфера», и проверка.

Битый или истёкший токен не сохраняется: приложение сначала спрашивает
у сайта «кто я», и кладёт токен в хранилище, только если сайт ответил
именем аккаунта.

Ты входишь на сайте сам, в браузере. Приложение не спрашивает логин
и пароль, не логинится за тебя и не проходит капчу — оно только
пользуется твоей уже открытой сессией. Токен лежит в keyring,
в конфиге его нет.

Истёк токен — сайт снова перестанет отдавать страницы, приложение
скажет об этом прямо и попросит свежий.

## Как это ходит на сайт

Только публичный JSON-API mangalib, без логина и без обхода капчи.
У API два адреса — `api2.mangalib.me` и `api.cdnlibs.org`. Любой из них
может целиком начать отвечать 403, поэтому приложение пробует оба.
Между запросами пауза 0.7 сек, один поток, User-Agent — имя приложения.
Картинкам сайт требует заголовок `Referer` (защита от хотлинка) — он
отправляется, больше ничего не подменяется.

Раздел тайтла (обычный, ранобэ, закрытый) определяется по ссылке,
а если хост незнакомый — перебором. Если главы сняты по требованию
правообладателя, приложение честно скажет об этом и остановится.
На такой случай есть `--local`.

## Где что лежит

- настройки: `~/.config/mangakindle/config.toml`
- кэш страниц: `~/.cache/mangakindle/` (чистится после сборки)
- готовые файлы: `~/MangaKindle/`

## Сборка релиза

Сборки Linux и Windows делает GitHub Actions, локально ничего собирать
не нужно. Релиз запускается тегом:

```bash
git tag v0.1.0 && git push origin v0.1.0
```

Workflow прогоняет тесты, собирает через PyInstaller два бинарника
на каждую платформу — `mangakindle` (командная строка, ~30 МБ) и
`mangakindle-gui` (окно, ~100 МБ) — и вешает архивы на релиз.
Тесты на каждый push в main гоняет отдельный workflow.

## Тесты

```bash
uv run --group dev pytest
```

## Предупреждение

Файлы предназначены только для личного чтения. Не выкладывай их
и не распространяй — это нарушает права авторов и издателей.
